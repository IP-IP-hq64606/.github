<h2>先纠正一个误解：地址数和带宽不是「此消彼长」</h2>
<p>常见说法是「地址越多，每条分到的带宽越少」。这个说法在「同时使用」的前提下成立，但容易被误解成「加地址会让带宽变小」。</p>
<p>准确表述是：带宽是一条线路的总量，地址只是出口标识。不用的地址不消耗带宽；同时活跃的地址越多，每个能分到的越少。</p>

<h2>数量上限由地址段决定</h2>
<p>能分几个地址，取决于上游分配给你的地址段大小，与带宽无关。买 10M 带宽也可以拿到四个地址，买 100M 也可能只有一个。两者是独立的采购项。</p>
<p>所以「能分几个」这个问题，答案来自合同而不是带宽。带宽影响的是「这些地址够不够用」，不是「能拿到几个」。</p>

<h2>但带宽会被分摊，这才是真实感受</h2>
<p>地址配好之后，所有地址共享同一条线路的总带宽。如果四个地址上同时跑重任务，每个能用的带宽约为总量的四分之一（还要扣掉协议开销）。</p>
<p>这就是为什么「多地址」和「高带宽」要一起考虑。只加地址不加带宽，结果是每条都慢；只加带宽不加地址，多出来的带宽用不上。</p>

<h2>估算公式</h2>
<p>每个地址可用带宽 ≈ 总带宽 × 有效系数 ÷ 同时活跃的地址数。有效系数通常取 0.85 到 0.95，扣除协议与封装开销。</p>
<p>注意分母是「同时活跃」，不是「地址总数」。只有一个地址在跑的时候，它能用接近全部带宽。所以估算要按业务高峰时段的同时活跃数来算。</p>

<h2>并发与端口的关系</h2>
<p>地址提供的是「源地址的数量」，端口提供的是「同一地址上并发连接的数量」。两者常被混为一谈。</p>
<p>一个地址理论上可以支撑数万个并发连接，实际受设备内存与连接跟踪表大小限制。所以「地址不够」和「连接不够」是两个不同的问题，前者靠加地址，后者靠调设备。</p>

<h2>一个估算示例</h2>
<p>假设总带宽中等档，四个地址，高峰时同时活跃三个，每个地址上的业务单用户需求不高。按公式估算，每地址可用带宽约为总量的三成，剩余一成留作波动余量。</p>
<p>如果实测发现某地址明显更慢，先确认它上面的业务是否更重，而不是立刻判断「地址有问题」。分配不均比线路问题更常见。</p>

<h2>什么时候该加带宽，什么时候该加地址</h2>
<p>加带宽的信号：所有地址都慢，且慢的程度接近；高峰时段整体下降；单地址跑满时其他人明显受影响。加地址的信号：不同业务需要独立身份；某些地址的用量长期偏高。</p>
<p>判断标准是「慢是普遍还是局部」。普遍慢加带宽，局部慢调分配或加地址。</p>

<h2>按「最忙那一刻」算，不按平均值算</h2>
<p>带宽规划最常见的错误是用日均值做依据。业务总有集中时段，那个时段的峰值才是真实需求。算的时候把所有地址在最忙一小时的同时用量加总，再留三成余量，得到的数字比平均值靠谱得多。</p>
<p>如果这个数字明显高于现有带宽，先别急着升级。看看能不能把批量任务挪到低谷时段，很多「带宽不够」其实是使用节奏问题。</p>
<h2>常见问答</h2>
<h3>地址多了会让带宽变少吗？</h3>
<p><strong>答：</strong>不会自动变少。只有同时使用、共享同一线路时，才会分摊。</p>
<h3>一条专线最多能给几个地址？</h3>
<p><strong>答：</strong>取决于分配给你的地址段，与带宽无关。以合同为准。</p>
<h3>怎么判断是带宽不够还是地址不够？</h3>
<p><strong>答：</strong>看慢是普遍还是局部。普遍慢是带宽，局部慢是分配或地址。</p>
<h3>并发连接数受地址限制吗？</h3>
<p><strong>答：</strong>不直接受限。主要受设备内存与连接跟踪表限制。</p>
